# 新宿（astrbot_plugin_shinjuku）

基于 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 的原生上机计费插件，用于新宿音游窝的会员、入场、计费与结算。数据使用 **SQLite 本地存储**
- 插件名：`astrbot_plugin_shinjuku`
- 显示名：新宿
- 版本：v0.4.0
- 最低 AstrBot 版本：>= 4.16

--若有音游窝计费需求，请在使用前联系作者（新宿音游社 QQ 群：1064813917），以便作者了解使用情况、提供后续更新与支持。

## 功能特性

- 会员注册：QQ 号自动绑定，支持管理员代注册
- 入场/退场计费：白天/夜晚两档时段、按小时计费、分时段封顶、24 小时逐块封顶
- 自助开门：默认要求积分严格高于 10；满足条件时入场会生成验证码，可使用 `/开门`，积分不足时仍可正常 `/login`，但不生成验证码，需联系管理员开门
- 偷偷上机：功能开关开启后，仅已注册且积分严格高于配置门槛（默认 10）的用户可用 `/偷偷上机` 入场；计费流程与 `/login` 一致，但会话单独标记为「偷偷上机」，在账单、历史记录和管理员在线列表中与普通入场完全区分；偷偷上机玩家在所有展示 QQ 昵称或 QQ 号的位置一律显示为「未知玩家」，且 bot 会通过 OneBot API 自动撤回玩家发送的偷偷上机指令及其退场指令消息（仅 aiocqhttp 平台生效，撤回失败不影响入场/退场），开关关闭后匿名显示与指令撤回完全不生效
- 月卡（通行证）：月卡用户享受更低的单价与封顶价
- 优惠券：管理员可发 X 折（0–10 折）优惠券，结算自动抵扣，单次使用作废
- 欠费机制：余额不足时仍可退场，差额记为负数余额；欠费期间禁止入场，充值补齐后解除
- 钱包体系：付费余额 / 免费余额 / 优惠券 / 通行证
- 金额精度：数据库与业务计算统一使用整数“分”，输入和显示仍使用“元”；折扣结果按四舍五入精确到分，避免浮点累计误差
- 兑换码：支持管理员生成兑换码（可设领取次数），注册礼包可直接配置兑换码自动发放
- 资产流水：所有资产变动写入日志，可追溯
- 店内人数：群内直接发送 `j`（或 `xsj`、`新宿几`、`窝几`、`wj`、`新宿j`）查询当前在线人数
- 昵称缓存：按平台、群聊和 QQ 隔离，3 天未刷新自动过期，最多保留 2000 条；用户再次触发相关指令时会记录当前昵称
- 数据完整性：数据库强制保证同一 QQ 只绑定一个用户、每个用户最多一个活跃会话，并禁止活跃会话的开门验证码被替换
- 并发安全：资产定义和兑换码由唯一索引保护；兑换使用立即事务，确保领取上限和一次性礼包不会被并发突破

## 配置项

设置表单由 `_conf_schema.json` 生成，在 AstrBot Web 控制台的插件配置页中修改。

### 基础配置

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `database_path` | string | 空 | SQLite 数据库文件路径；留空则默认存放在 AstrBot 数据目录 `plugin_data/astrbot_plugin_shinjuku/shinjuku.db`，删除插件不丢数据；也可填绝对路径 |
| `currency` | string | 馕 | 货币显示名 |
| `admins` | list | [] | 管理员用户 ID（QQ 号），可执行管理指令 |
| `redeem_code_on_register` | string | 空 | 注册后自动发放的兑换码；留空注册不送礼 |
| `points_per_amount` | int | 10 | 封顶积分折算金额（元）；触发封顶时每 10 元封顶得 1 积分（向上取整），正常时段按游玩小时数 1 小时 1 积分，设 0 关闭 |
| `max_active_checkcodes` | int | 20 | 同时存在的最大验证码数量（店内人数上限）；当前在线人数超过该值时，入场成功后追加提示 |
| `self_open_door_enabled` | bool | true | 自助开门开关；开启后入场生成 7 位验证码并允许使用 `/开门`，关闭后不生成验证码并提示联系管理员开门 |
| `self_open_door_points_threshold` | int | 10 | 自助开门开启时检查；可用积分必须严格高于该值才生成验证码，积分不足不影响 `/login` 入场 |
| `login_grace_minutes` | int | 3 | 成功使用 `/开门` 后的首小时门槛；从入场时间计算，不超过 3 分钟离场免费，严格超过后首小时按 1 小时计费；未开门及后续零头仍使用 15 分钟宽限 |
| `sneak_login_enabled` | bool | false | 偷偷上机功能开关；开启后 `/偷偷上机` 可用，关闭后指令不响应，与未修改版本行为一致 |
| `sneak_login_points_threshold` | int | 10 | 偷偷上机积分门槛；可用积分必须严格高于该值，等于该值时不允许偷偷上机 |

### 计费规则（`billing`）

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `day_start` / `day_end` | 11:30 / 00:00 | 白天时段 |
| `day_price` / `day_price_pass` | 12 / 11 | 白天每小时价格（普通 / 月卡） |
| `day_cap` / `day_cap_pass` | 69 / 59 | 白天封顶（普通 / 月卡） |
| `night_start` / `night_end` | 00:00 / 12:00 | 包夜时段；已进入包夜计费的会话可持续到 12:00，11:30 后新入场用户仍按白天计费 |
| `late_day_start` | 23:00 | 该时间至 `day_end` 入场时，首小时完整按白天价格计费，即使跨过午夜 |
| `night_cap_cover_start` | 23:30 | 该时间至 `day_end` 入场时，首小时白天费用与后续夜间费用合并参与包夜封顶，不再额外叠加 |
| `night_price` / `night_price_pass` | 13 / 12 | 夜晚每小时价格（普通 / 月卡） |

## 计费规则

- **时段**：白天 11:30–00:00，包夜 00:00–12:00，均按小时计费；11:30–12:00 为重叠时间，已有包夜会话继续按夜晚计费，11:30 后新入场用户按白天计费；
- **深夜入场**：23:00–00:00 入场的首小时完整按白天价格计费，即使跨过午夜，例如 23:30–00:30 只收 1 小时白天费用；
- **包夜覆盖**：23:30–00:00 入场时，首小时白天费用与后续夜间费用合并参与包夜封顶；合计达到封顶后只收包夜封顶，不再额外叠加首小时费用；超过 12:00 后继续游玩则另计白天费用；
- **取整**：成功使用 `/开门` 的会话从入场时刻起，首小时严格超过 `login_grace_minutes`（默认 3 分钟）即按 1 小时计费；未成功开门的首小时及所有后续零头，仍按 `grace_minutes`（默认 15 分钟）处理，零头不超过该值时不增加小时数；
- **分时段封顶**：每个白天时段/夜晚时段分别封顶（普通 69 / 月卡 59）；
- **24 小时封顶**：从入场时刻起按 24 小时切块，每块单独封顶（普通 99 / 月卡 88），超过 24 小时按块累加；
- **月卡**：持有通行证的用户按月卡单价与封顶计算；
- **优惠券**：结算时自动选择折扣最大的一张（0–10 折），全程使用整数分和整数折扣基点计算，折后价四舍五入到分，使用后作废；
- **欠费**：余额不足仍可退场，差额记为负数余额；负余额期间禁止入场，充值到 0 或以上后解除；退场消息会提示"请联系主理人补款"。

### v0.3.0 金额迁移

插件首次以 v0.3.0 启动时，会在同一事务中自动把旧数据库里的货币余额、资产流水、历史账单和礼包货币金额从“元”迁移为整数“分”，并记录迁移标记，后续启动不会重复转换。积分、优惠券数量和通行证数量不会乘以 100。升级前仍建议备份 SQLite 数据库文件。

## 兑换码与礼包

- 礼包（`Present`）定义礼包内容，兑换码（`Redeem`）绑定礼包并设置生效/过期时间与总领取次数（`maxUseCount`，默认 1 次）；
- 每个用户对带 `oncePerUser` 的礼包限领一次；同一兑换码按总领取次数封顶；
- 管理员可用 `/giftcode` 基于现有礼包生成兑换码（货币数量按参数覆盖，人数封顶按参数设置）；
- 注册礼包：配置 `redeem_code_on_register` 后，新用户注册时自动用该兑换码领取；码无效/用完不会阻塞注册，仅在回复中提示失败原因。

## 数据存储

- 默认数据库：AstrBot 数据目录 `AstrBot/data/plugin_data/astrbot_plugin_shinjuku/shinjuku.db`（通过 `StarTools.get_data_dir()` 获取，删除插件不丢数据；可在配置 `database_path` 指定其他路径）；
- 自动建表：`User`（用户）、`Bind`（平台绑定）、`Session`（会话）、`Asset`（资产定义）、`UserAsset`（持有资产，数量可为负表示欠费）、`UserAssetLog`（资产变动流水）、`Present`（礼包）、`Redeem`（兑换码）、`RedeemRecord`（兑换记录）；新宿日麻开启联动后，会在同一数据库中额外维护独立的 `MahjongRank` 与 `MahjongMatch` 表；
- 备份：直接复制数据库文件即可；数据库采用 WAL 模式，备份前建议关闭插件。
